# 文件、会话与中断恢复优化

本轮落实痛点分析中的前三项：文件内容可靠性、会话状态隔离与中断后接续。沿用当前开发版本号，不包含发布或手机安装。

## 文件处理

- XLSX 按单元格的列坐标补齐空列，支持多字母列号；`A2=Alice`、`C2=100` 会保留中间的空 B 列。列范围及生成文本长度仍受限制。
- 文档内容继续保存在消息的附件字段中。超过 6,000 字符时，请求只携带开头预览、消息 ID 与分页读取说明，避免把允许导入的 40,000 个中文字整体塞入 32,000 Token 的请求预算。
- 新增只读 `read_attachment`：按本会话的消息 ID 和字符偏移读取，每页最多 6,000 字符；返回总长度、下一页位置、是否仍有内容及源文件是否已截断。支持纯聊天模式，不要求 Power 或命令权限。
- 分页使用原始保存文本，保留首尾空白并避开 Unicode 代理对边界。拒绝越界位置、其他会话的消息、图片和无效参数。
- 上下文整理按实际预览计算附件占用；对长附件的短追问不会仅因本地保存了全文就额外发起摘要请求。
- 原有 20 MiB 文件及 80,000 字符提取上限保留；超过提取上限的内容仍明确标为截断。扫描 PDF 的 OCR 和多附件输入不在此次范围内。

## 会话与执行

- 草稿、待发送附件、附件加载状态、错误和运行状态按会话保存。异步附件读取完成后回到原会话；发送启动期间新输入的草稿不会被清空。
- 不同会话可以同时请求模型；停止一个会话只取消该会话的回复和命令。每轮的模型、工作区、工具证据、确认及命令授权分别保存。
- 手机工具在实际执行时取得互斥锁，避免多个任务同时操作屏幕。锁保留到原任务结束及取消清理完成，排队任务不能抢占设备。
- 任务开始时即记录用户接管边界，等待模型期间发生的前台返回仍会阻止迟到的手机操作。后台确认期间返回应用的既有规则保留。
- 浮窗跟随正在控制手机的会话；浮窗停止和回复绑定该会话。另一个会话等待确认时，主界面提供「查看确认」入口。

## 中断与接续

- 每次应用进程初始化，Room 在事务中恢复未结束的助手与工具记录；同一仓库实例只执行一次，避免页面重建误判正在执行的任务。
- 保留部分回复、附件、推理展示与工具结果。未返回的工具意图标为 `interrupted_unconfirmed`，不把请求过的操作当作已完成。
- 最新一轮没有完成答复时显示「继续任务／结束任务」。继续会重新读取该会话的持久记录，要求先核验未确认操作；结束写入完成的结束记录，重开后不会反复显示同一恢复卡片。
- 上述功能恢复任务证据与人工接续入口，不重建已经终止的系统进程或自动重放命令。

## 验证

单元测试覆盖稀疏列、长附件预览与分页、会话隔离、并行回复、停止隔离、异步附件归属、启动期间输入、接续的会话归属、结束与发送竞争，以及数据库恢复的事务、幂等性和证据保留。

设备使用 MuMu 0（Android 15），ADB 串号 `127.0.0.1:16384`。新增 `ProductReliabilityDiagnosticTest` 使用合成数据、真实 Room、实际 Activity 和本地 HTTP 模型；不调用外部模型。覆盖恢复卡片显示与结束、稀疏 XLSX、40,000 字符附件读回、实际 `read_attachment` 工具续轮，以及并行会话与停止。测试恢复原设置并清理合成会话及临时服务商。

构建与设备日志保存在忽略目录 `build/optimization/`；恢复界面截图为 `build/optimization/recovery.png`。

最终结果：

- 全量 420 项单元测试：419 通过、1 项既有 Windows 符号链接环境用例跳过，零失败。最终日志 `final-build-2.log`。
- Debug、AndroidTest、Release 构建成功，Release lint/R8 检查通过。
- 新增设备测试 3 项通过（`device-reliability-final-2.log`）。其中实际模型请求先收到有限预览，再通过 `read_attachment` 读回唯一的文件尾部标记，最终完成答复；恢复卡片结束操作真实写回数据库。
- 既有设备回归 10 项通过（`device-regressions.log`）：后台确认与普通返回接管、实际 Linux 命令执行、5 项屏幕读取、工作区文件传入与写回、检查点与原始证据回读、停止后的任务接续。另 1 项需显式开启的真实 DeepSeek 测试按默认规则跳过。
- Debug APK 已覆盖安装到 MuMu；SHA-256 为 `B28C2F997F435E1D351F16108AF9DB70A791E8DF3758BB5B11E527FDA458AD6D`。

验证中发现并处理了两项新测试问题：最初 JUnit 方法推断出非 Unit 返回值，改为显式 `runBlocking<Unit>`；实际附件工具测试随后暴露预算仍按保存全文计算的问题，修复预算后整组重跑通过。最终结果不包含早期失败运行。
