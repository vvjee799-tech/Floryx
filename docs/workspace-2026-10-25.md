# 手机文件夹工作区

设置入口：侧边栏 → 设置 → 工作区。通过 Android 系统文件夹选择器，选择手机上已有的文件夹并授权访问。页面显示文件夹名称、位置和可读写状态。

当前会话保存自己的关联；开启「设为新会话的默认工作区」后，新建会话复制该设置，其他已有会话不变。取消关联只移除设置，保留手机文件与本地执行文件。运行中的任务固定使用启动时的工作区，新选择在下一次任务生效。

授权持久保存。文件夹移动、被删除或授权被撤销时，页面显示「需要重新授权」，重新选择文件夹即可恢复。只读文件夹可以读取资料，写回结果需要写入权限。系统文件夹选择器遵循 Android 的可选目录范围。

## 文件与命令

选择工作区后，模型可按任务浏览、读取 UTF-8 文本、保存和重命名文件。普通文件操作使用系统文件夹授权，不需要 Power。脚本处理继续使用现有的「允许 AI 执行命令」开关。

手机文件夹使用 SAF 文档 URI；当前 Linux 命令行需要真实文件路径。因此脚本使用本地执行副本：按需导入指定文件，在 `/workspace/phone/<workspace-key>` 处理，再将指定结果写回原文件夹。该目录按会话分别保存，工作区键来自授权 URI 的摘要。没有递归复制整个手机文件夹，也不把文档 URI 伪装成可挂载的文件路径。

`run_command` 的 `workspace_inputs`、`workspace_outputs` 都使用相对工作区的文件路径。命令成功退出后，应用保存指定输出并校验 SHA-256；返回的 `workspace_saved` 和 `workspace_errors` 分别表示实际保存结果与失败原因。失败、取消和超时不自动发布输出。

在执行命令前登记输出目标及原文件修订值。任务停止后，已生成的输出保留在本地；继续任务可以使用原执行副本。写回失败时保留输出与目标关联，设置页提供「待保存结果」，重开应用后仍可重试。重试使用原文件夹，避免更换工作区后保存到错误位置；保存回执显示实际文件夹、文件名和冲突副本状态，并按会话显示。

文件修订使用实际内容 SHA-256。文件被其他应用修改或删除时，写回保留冲突副本并报告实际保存位置。直接修改已有文本时，模型应提交读取返回的修订值；缺少修订值时保留原文件并创建副本。重命名核对修订值且不覆盖同名文件。

## 范围和接口

- 每次列目录最多 50 项，提供后续偏移量。
- 文本文件上限 256 KiB，每次返回最多 12,000 字符并提供分页位置。
- 命令文件传递每批最多 32 个文件，单文件 20 MiB、整批 64 MiB。
- 路径必须位于所选工作区；拒绝绝对路径、父级跳转及无效会话标识。
- Linux 仍是原有 PRoot 环境；工作区关联与执行目录用于组织文件，不构成安全沙箱。

模型接口：`workspace_status`、`workspace_list`、`workspace_read`、`workspace_write`、`workspace_rename`；开启命令后提供 `workspace_import`、`workspace_publish`。工作区上下文在任务压缩后重新注入。

## 存储与迁移

数据库升级到 13，在会话增加可空的 `workspaceJson`，已有会话保持未关联状态。默认工作区保存在原有设置存储中。执行文件继续放在 `files/terminal/workspaces/<conversation-id>`，待保存记录位于 `files/workspace-transfers`，采用临时文件写入和原子替换保存记录。
