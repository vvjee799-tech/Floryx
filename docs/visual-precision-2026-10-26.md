# 视觉点击精度修复（1.5.18）

用户反馈实机点击容易偏上，并指定参考 Floryx 关于自身缺陷的回复。只读查阅指定回复及相关工具证据，未读取模型推理或服务商凭据。

## 确认的问题

- 实际记录中存在多次 `run_command` 内的 `input tap`。这些坐标直接交给 Android，没有绑定截图来源、裁剪区域或当前画面，视觉工具的检查没有覆盖这条回退路径。
- 原流程允许模型根据整屏截图一次估计 0–1000 坐标并点击。小图标在长截图中占比低，估计误差会放大到实际屏幕。
- 点击触发窗口变化时，后续截图可能恰好落在窗口交接期间，返回 `screen_changed_during_capture` 或暂时不可读，缺少稳定的新图验证。
- vivo 的浮动测试窗口进场期间，曾返回超出显示器范围的窗口边界。截图虽有像素，安全映射尚未建立，不能马上用于点击。该现象与控件树为零分别处理，不把无控件等同于没有视觉能力。

这些证据支持修复执行链路；不能仅依据模型自述断定存在固定的纵向偏移。因此没有给坐标硬加一个补偿值。

## 改动

1. 大图仅选区。来源区域最长边大于 800 像素时，首次视觉点击只返回约 640 像素范围的局部新图，标明 `visual_refinement_required=true`、`gesture_dispatched=false`，不派发手势。
2. 在新图中重新定位。模型需要复制新的画面 ID，以局部图片为坐标系再次选择目标。局部区域限定在此前可见范围内，不混用旧图或整屏坐标。
3. 精确点击仍核对目标像素、窗口、旋转、遮挡和用户接管状态，然后回传操作后的新图。可靠控件仍优先使用控件编号。
4. AI Android 命令中的常见裸坐标点击、滑动及应用启动，改为要求使用对应设备工具，在执行或请求命令授权前返回说明。普通诊断和文件命令保持可用，手动终端不受 AI 调用规则影响。这是工具路径约束，不是完整 Shell 沙箱。
5. 短暂窗口变化和取图失败最多重试两次，间隔 180/360 毫秒；有图但窗口映射尚未建立时也等待新图。敏感、系统禁止截图或真实遮挡不会通过重试放开。

## 验证

小目标测试故意把初次坐标向上偏移，再检查没有提前发生点击。第二次根据局部图重新定位；测试页用实际 `MotionEvent` 落点绘制红点，以像素比较落点和原目标中心，而非仅检查派发成功。

最终结果：

- 全量单元测试 471 项：470 通过、1 项既有 Windows 环境用例跳过，零失败。
- Debug、AndroidTest、保留配置 Release/R8 构建通过；Debug Lint 为 0 错误、174 条既有警告。
- MuMu 联合回归 21 项通过。JUnit 共列出 22 项，其中付费真实模型用例默认跳过，另行显式执行。
- 使用 MuMu 既有 DeepSeek Flash 配置，真实模型完成“整图选区 → 局部重新定位 → 实际点击 → 确认变绿”；未配置或导出新密钥，只发送专用测试页面。相关证据为 `live-flash-2.log` 与 `mumu-live-precision-evidence.json`。
- 用户明确允许手机四点校准后，在 vivo V2302A、Android 16、1260×2800 上完成同一套实际触点测试。四个目标均命中，各方向误差均不超过 2 像素：

| 位置 | 水平误差 | 竖直误差 |
| --- | ---: | ---: |
| 顶部小目标 | 2 px | 1.5 px |
| 中部小目标 | 2 px | 1 px |
| 底部小目标 | 2 px | 1 px |
| 偏移浮动窗口 | 1.5 px | 2 px |

手机前三个点首次已能命中；浮动窗口校准暴露进场时不可映射的画面，补充有限重试后通过。另修正了独立运行校准用例时结果目录未创建的问题。最终通过结果以 `phone-calibration-final.log`、`phone-precision-result.txt` 为准，早期失败不计入通过统计。
