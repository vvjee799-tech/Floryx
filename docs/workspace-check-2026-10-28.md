# 工作区生效检查（2026-10-28）

结论：工作区设置、会话关联、持久文件夹授权和正常文件写回均能生效；同时，已在 MuMu 复现“命令生成了文件，但所选文件夹仍为空”的两种情况。不能把命令成功退出当作文件已保存。

本次验证使用 MuMu `127.0.0.1:16384`、当前源码 1.5.20（34）、Floryx Dev、系统文件夹选择器和 `Documents/FloryxWorkspaceQA`。模型由本地测试服务器模拟，没有使用真实模型账户。未连接或读取实体手机，无法确定用户原会话具体命中了哪个条件。

| 验证场景 | 实际结果 |
| --- | --- |
| 选择文件夹、关联当前会话、设置新会话默认值 | 设置与关联保存成功，显示可读写；已有会话保留各自关联 |
| 使用 `workspace_write`，或在默认执行目录运行命令并提供 `workspace_outputs` | 文件写回所选文件夹，独立读回 `结果.txt` 的内容为“资料已修改” |
| 命令生成文件，但省略 `workspace_outputs`，随后也不发布文件 | 命令退出码为 0；文件仅存在应用内部执行副本，所选文件夹没有文件；保存结果和错误均为空，也没有待保存项 |
| 命令指定 `/workspace` 为工作目录，生成相对路径文件；输出仍按所选工作区声明 | 命令退出码为 0；保存返回 `Output file does not exist`；文件留在另一个内部目录，所选文件夹没有文件，也没有待保存项 |

两种空文件夹场景均由应用真实命令执行和文件系统检查验证，不是仅凭源码推测；模型不声明输出的情况属于当前显式传输设计。第二种情况说明命令工作目录与输出路径可以发生错配。它们是否对应用户手机上的那次操作，仍需要原会话的工具记录。
