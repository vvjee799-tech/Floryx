# 会话检查点与压缩

本版在 1.5.5 执行历史修复之上，借鉴 Codex 的持久化历史、上下文检查点和有界窗口管理。实现为 FlowChat 自有 Kotlin 代码，沿用当前会话配置的模型，支持现有多服务商接口，不嵌入 Codex 运行时。

## 记录、窗口和长期记忆

- 原始用户消息、答复、工具参数、返回结果与停止状态继续保存在本机数据库。
- 发送给模型的窗口由“较早历史的检查点 + 最近原始记录 + 当前指令”组成，不再按固定轮数直接丢弃未摘要的旧对话。
- 检查点保存任务目标、约束、发现、已完成步骤、失败尝试、用户纠正、剩余事项与不确定内容。每项带原消息 ID；另外保留原始任务和最近的用户指令，以及停止/失败记录索引。
- 当前会话上下文不受跨会话长期记忆开关控制。关闭记忆仍可继续本会话任务。
- 保留本机可展开的思考内容；已完成轮次的思考原文不再作为后续普通对话历史重复发送。当前工具续轮所需的推理文本和不透明签名仍保留。

## 压缩与恢复

当前开发版默认在约 24,000 Token 的请求预算触发摘要，硬预算仍为 32,000 Token；短对话不再仅因超过 16 轮而整理。整理时以约 12,000 Token 为目标选择可归档的前缀，并在下一次整理前留出至少约 4,000 Token 的增长空间；接近 30,000 Token 时优先处理上下文压力，32,000 的最终校验继续保留。通常保留最近 4 轮，过长活动可进一步整理，当前用户指令继续作为锚点。

预算按实际服务商协议投影估算，包括确实需要回传的推理和不透明状态；被原生块替代的字段不重复计算，不发送的推理不计入。JSON 传输层的转义不重复计入模型文本，图片沿用固定帧预算而不计算 Base64 字节。历史窗口和运行中工具循环使用同一投影与增长阈值。估算仍基于 UTF-8 启发式，不是服务商精确分词器，也不代表自动识别了模型的上下文上限。具体改动和前后对照见[长任务整理频率优化](context-frequency-2026-10-26.md)。

摘要是独立的禁工具请求，默认关闭思考，输出有来源的 JSON。普通首轮最多 4,096 输出 Token，已有摘要超过 6,000 字符时直接用 8,192，避免每批先截断再重试；每次限时 30 秒。JSON、内容形状、来源校验失败、输出截断或流未完成时，用同一批来源和具体反馈最多修复两次，修复轮最多 8,192 输出 Token；同类错误重复出现即停止，不执行工具或重复手机上的动作。HTTP 服务错误、超时和外部取消不进入这个修复循环。长历史按预算分批合并；只在收到完整结果、JSON 与来源校验通过后提交新的检查点。正常短对话不会增加摘要请求，发生压缩时显示“正在整理之前的任务记录…”，并使用当前服务商额度。

摘要提示要求重写合并旧摘要，目标不超过 16 项、6,000 字符，避免按操作逐条累加。程序在每条文字和来源校验通过后，归并同一分类的相邻短条目，减少重复来源索引，保留原文顺序和全部有效来源；新归并的组合以 500 字符、16 个来源为界。条目数、单项长度与引用数是格式建议，完整有效的长条目或更多有效引用不会单独触发停止。流输出暂存最多 24,000 字符，供完整解析和无损归并；归并后按 UTF-8 估算不超过 8,000 Token，完整检查点不超过 16,000 Token。非空内容、每项至少一个来源、来源属于本会话、完整流和 JSON 仍严格校验；总请求的 32,000 Token 硬预算继续单独检查。无法在预算内保留内容时继续纠正或明确失败，保留原始记录。

检查点记录覆盖边界及原记录指纹。Room 事务在写入时再次检查原记录和上一检查点；已变化的来源、被删除的会话或竞争写入不能被旧摘要覆盖。重新打开会话时复核指纹，再恢复窗口。

摘要失败、超时或取消不删除原记录，也不覆盖上一个有效检查点。分批整理若只完成一批，后续未覆盖记录仍完整进入窗口。失败后短时间内抑制重复摘要请求；若仍超过硬预算，则明确停止本轮，避免带着残缺历史继续执行操作。

停止时将具体原因保存进答复，区分摘要格式、超时、输出截断、连接中断及服务商返回的 HTTP 状态；重开会话仍可看到原因。原记录和检查点保留在原会话中。

## 单轮长任务

工具循环也检查预算。压缩较早步骤时，按回传体积保留最近 1–2 组完整的原生助手调用与工具返回；近期数据较小时保留两组，过大时保留最新一组。每组的全部调用、返回、相关推理和服务商签名一起保留，不拆开配对，不对原生回传字符串二次裁剪。较早记录只有在有源检查点提交成功后才离开原生窗口，原始任务记录继续保存在本机。

DeepSeek 思考模式携带工具定义时，要求原生助手消息完整回传思考字段。1.5.9 为本地重建的历史和摘要增加来源标记；这类投射在 DeepSeek 请求中作为明确引用的历史数据传入，保留角色说明和证据，不冒充缺少回传状态的原生助手消息，不伪造思考内容。当前仍在执行的原生调用及推理字段保持原样；其他协议和关闭思考、无工具的请求维持原有格式。

已压缩的记录没有从数据库删除。模型可以调用只读的 `read_task_history`，按检查点来源 ID 回读本会话原始消息和工具证据；一次 1–4 条、总输出有界，长记录标明摘录。它不读其他会话或原始思考，不要求 Power 模式，也不提供新的设备操作授权。

## 与 Codex 的边界

源码参考和修复起因见 [任务上下文说明](task-context.md)。这里移植的是上下文管理原则；没有把 OpenAI Responses 的不透明原生压缩条目转交给其他服务商。摘要仍可能遗漏或误解信息，因此保留来源、原记录和回读能力；不能保证所有模型永远不重复步骤。

数据库 10 → 11 为 conversations 增加可空检查点字段；旧配置、聊天和 1.5.5 执行证据保留。

## 验证范围

单元测试覆盖正常压缩、来源错误、流未完成、摘要禁工具、取消、失败回退、分批中断、来源变更、只读会话隔离、重新创建管理器、真实 Room 迁移及事务比较、单轮长任务的原生调用/结果/签名配对。

MuMu 定向测试通过本地 HTTP 模型端点验证实际摘要请求、数据库存储与重新读取，以及回读原始工具证据的完整请求链。真实模型验证使用单独创建的合成测试会话；为复现真机摘要故障，另使用经过脱敏的对应历史进行只生成摘要、禁工具的重放。临时会话、服务商和重放文件在测试后清理。

1.5.9 验证（2026-10-23）：337 项单元测试中 336 项通过，1 项既有 Windows 符号链接环境用例跳过，零失败。测试包含多阶段纠正、无损归并的文字顺序与来源、重复索引导致体积增长、大检查点的输出额度、按估算 Token 预算判断，以及超过格式建议但来源有效且预算内的摘要。Debug、设备测试包、保留安装身份的 Release 与 Release lint/R8 构建通过。

MuMu 六项定向回归通过：严格 DeepSeek 协议历史投射、运行中压缩、无效摘要修复、输出截断修复，以及真实 DeepSeek 的历史证据续接和大记录摘要。三个长任务场景均执行 8 次预定的只读历史查询、9 次回答请求，零缺失思考字段、零协议拒绝；修复摘要不增加工具操作次数。整理状态确实写入界面消息。

真实 DeepSeek 在合成会话中准确回答“不需要重新安装”，未重做检查。另一项测试将 25 条大记录整理为有效检查点和 5 条近期记录，估算请求约 12,284 Token，低于本地硬预算；该次测试使用优化批预算之前的配置，共使用 10 次分批摘要请求。以上不等于证明任意真实任务都能正确诊断或修复，仍需检查工具证据与用户实际症状。

真机复杂历史曾连续出现摘要截断、旧摘要累积至 53 项被拒绝的问题。使用经过脱敏的同一段记录在 MuMu 重放，复现后完成修复；最终构建重放以 2 次摘要、约 50.7 秒完成，失败码为空。来源有效、预算内的 527 字符条目及 17 个引用没有再被当作格式错误拒绝；摘要内容没有触发手机操作。
