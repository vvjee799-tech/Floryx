# 聊天体验、性能与会话管理优化

本轮按优化清单的 1、2、3、6、7 项实施。源码仍使用 1.5.18 开发版本号，未发布新安装包。

## 阅读与滚动

- 位于底部时跟随最新回复；用户向上阅读后暂停跟随，显示「回到最新」。新发送的用户消息会重新跟随。
- 「加载更早消息」按原消息 ID 和像素偏移恢复阅读位置，避免历史插入后跳到新加载内容。
- 每个会话独立创建列表状态。向前分页发现旧用户消息，不会误判为刚发送的新消息。

## 流式写入与历史分页

`StreamingReplyWriter` 使用 StringBuilder 合并网络片段，界面约每 50 ms 更新一次，数据库约每 350 ms 保存一次。工具／协议边界和正常取消会保存剩余数据；没有待刷新内容时不持续调度定时任务。应用进程被系统直接终止时，最后一个保存间隔内尚未落盘的片段可能丢失，已有中断恢复会继续使用已保存记录。

合成测试依次输入 200 个思考片段和 200 个答复片段，各间隔 5 ms，结果为 **41 次界面快照、7 次数据库写入**，最终文字与思考完整一致。这是合成流的写入次数对照，不代表所有设备的耗时或内存收益。

界面首次读取最近 80 条消息，每次加载再扩展 80 条；SQL 使用会话与时间索引。发送模型请求、导出与上下文预算仍读取完整持久历史。另有回归覆盖用户消息位于显示页之外的长任务，恢复入口继续可用。

## 回复展示

使用 CommonMark 解析器并接入 GFM 表格、删除线和自动链接。支持标题、加粗、斜体、列表、引用、分隔线、表格、行内代码与代码块。解析在后台执行，原始消息保持不变。

代码块保留原始复制内容，长行在代码区域内横向滚动；表格也在独立区域内滚动。网页和邮件链接可点击，HTML 作为文字显示，图片使用替代文字和链接展示。

## 会话管理

- 搜索标题、消息正文与已保存的附件文字／文件名；搜索框输入限频，SQL 通配符按普通字符处理。
- 行末菜单提供重命名、置顶、归档、恢复、导出与删除；删除沿用确认流程。
- 活跃与归档会话分开浏览，置顶优先排列；状态由 Room 保存，数据库 13 → 14 迁移同时建立历史查询索引。
- 导出通过 Android 文件选择器保存 Markdown，包含原始正文、思考、状态、附件文字与时间；图片附件仅记录名称。导出运行中会话时会合并当前内存快照。

## 验证与复跑

新增测试覆盖流式合并、取消保存、部分失败、Markdown 结构和链接、导出内容、正文搜索、分页稳定性、迁移后重开、完整模型历史与长任务恢复。旧的滚动和流式字符串断言改为行为测试。

MuMu 的专门用例覆盖实际触摸回看、持续更新、恢复跟随、分页阅读锚点、代码复制、链接点击、窄屏深浅色／大字体、重命名、置顶、正文搜索和归档恢复。

一键验证：

```powershell
.\scripts\verify-chat-optimizations.ps1
```

脚本运行全量单元测试、Debug／AndroidTest／Release 构建与 Release lint，随后通过 MuMuManager 查询实例 0 的实际 ADB 端点，必要时启动该实例，只向它安装测试包并运行新旧联合回归。`-BuildOnly` 可仅执行构建检查。日志位于 `build/chat-optimization/`，截图位于该目录下的 PNG 文件。

- 全量 482 项单元测试：481 通过、1 项既有 Windows 符号链接环境用例跳过，零失败。包含新增的完整模型历史与长任务恢复用例。
- Debug、AndroidTest、Release/R8 构建与 Release lint 通过；lint 为 0 错误、164 警告。
- MuMu 0（Android 15），由 MuMuManager 核实 ADB 端点为 `127.0.0.1:16384`。12 项联合设备回归全部通过：新增聊天优化 4 项、产品可靠性 3 项、上下文 3 项、输入底栏 1 项、浮窗输出 1 项。
