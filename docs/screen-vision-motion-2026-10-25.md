# 动态画面修复（1.5.14）

## 手机记录与原因

按用户要求，只读查询手机 Floryx 最新用户消息及同轮执行记录，并补读紧邻的相关上下文，没有导出服务商密钥或完整数据库。最新一轮问题发生在 2026-10-25 13:07：用户询问能否读取所有画面，首次 `observe_screen(include_image=true)` 返回 `screen_changed_during_capture`，随后模型暂停视频、调用 `wait_for_screen` 成功获得截图，再恢复播放。成功结果记录了 `image_available=true` 与 864 × 1920 图片尺寸，说明图片通道已工作，不能将失败归因于只支持控件文字。

1.5.13 在捕获前等待控件稳定，并要求截图前后的所有控件完全相等。`hasSameUi` 包含文字、边界和状态；播放进度、动画或计数变化足以令一帧有效截图被丢弃。历史记录没有保留失败前的完整控件树，无法单独断定是哪一个控件触发了变化，但上述过严判定在代码中明确存在。邻近回复还将“没有可读控件”等同于无法读取画面，模型为验证截图而暂停播放也超出了只读观察需要。

## 修复

- 截图前读取当前控件一次，不等待静止。自绘画面没有文字或可操作控件也可捕获一帧。
- 截图前后验证应用包名与实际窗口 ID，仍拦截敏感页面、窗口切换和系统保护；同一窗口的动画、标题或控件更新允许返回图片。
- 截图后读取最新控件，以新的 `screen_id` 绑定工具结果，并分别提供图像和控件采样时间。模型明确获知两者并非原子采样，动态内容可能存在差异。
- 点击和输入保持目标检查，补充同一应用内的窗口 ID 校验；获取一帧图片不等于允许沿用旧控件操作。
- 全局回复规则和看屏幕工具说明要求按当前画面只读观察；不得为了获得静止截图擅自暂停、恢复播放或改变页面。没有控件时先依据实际图片结果判断能力，不照搬旧的无障碍读取限制。

画面仍是单帧图像，不是连续视频或应用内部数据。系统禁止截屏的窗口继续不可读取。

## 验证范围

单元验证动态控件更新、没有可读控件、最新目标绑定、跨应用或窗口切换、缺失窗口身份、敏感页面和不匹配图片的拒绝行为。MuMu 使用专用图形页面持续移动图形并更新计数，再隐藏全部控件语义验证自绘画面。模型接口为本地模拟响应，不发送手机个人画面、不使用真实模型额度。

## 实际结果

- 383 项单元测试：382 通过、1 因 Windows 符号链接权限跳过，0 失败。
- Debug Lint：0 错误、174 条警告。Debug、设备测试包与 Release 构建通过，Release 包含 Lint Vital 与 R8 检查。
- MuMu Android 15（`127.0.0.1:16384`）13 项联合回归全部通过：4 项画面、5 项基础控件，以及工作区、输入框底栏、余额、用量各 1 项。
- 连续捕获 3 张不同图片时，页面计数继续变化；本地模型接收端解码动态图像并验证红、蓝像素。另一页面读取结果确实为 0 个控件，仍取得了有效图像。密码页与系统禁止截图的窗口继续不返回图片。

首轮零控件夹具失败，因为服务启用 `flagIncludeNotImportantViews`，标记为“不重要”的计数 TextView 仍被正常读取。修正测试页，将该计数控件移出零控件页面后，以相同的严格空控件断言复测通过。没有调整产品的控件读取标志。相关日志：`build/screen-vision-motion-build.log`、`build/screen-vision-motion-final-build.log`、`build/screen-vision-motion-device.log`、`build/screen-vision-motion-final-device.log`。

本轮未对真实模型重新发送付费指令；对模型只读行为的改动是系统规则与工具说明约束，设备验证采用本地模拟模型。Android 11–13 分支本轮未增加相应系统设备回归。
