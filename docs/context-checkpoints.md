# 会话检查点与长历史压缩

Floryx 借鉴结构化任务检查点与有界上下文管理思路，使用自有 Kotlin 实现支持多服务商的长对话与长任务上下文治理，不依赖特定厂商的不透明压缩服务。

## 上下文窗口策略

- **动态模型窗口预算**：
  - 对 DeepSeek 官方及已确认支持百万上下文的型号启用 **1M 上下文策略**，按实际输出上限与思考模式动态预留空间；
  - 对其他模型及未知自定义接口沿用保守的默认窗口预算（约 24,000 Token 触发整理，32,000 Token 硬预算），在后台异步计算与估算。
- **输入框上下文指示器**：输入框下方提供上下文占用圆环，点击可查看当前模型容量、输入预算、输出预留与已用估算比例。

## 检查点结构与局部保真

发送给模型的对话窗口由 **较早历史的检查点 + 最近保留的原始轮次 + 当前用户指令** 组成：

- **检查点内容**：结构化记录任务目标、约束条件、已确认发现、已完成步骤、失败尝试、用户中途纠正、待处理事项及不确定状态，且每条均关联本会话原始消息 ID。
- **工具循环内部压缩**：单轮复杂长任务中如果工具调用累积过多，会在预算边界内将较早的工具步骤整理入检查点，同时完整保留最近 1–2 组原生助手调用、工具返回、推理文本与不透明签名配对，不拆散工具调用链。
- **独立于长期记忆开关**：会话检查点用于维持当前任务的连续性，即使在设置中关闭跨会话的「记忆」功能，本会话的上下文治理仍正常工作。

## 可靠性与原始证据回读

- **有源 JSON 校验与原子提交**：摘要请求独立发出、禁用工具并关闭额外思考，输出需通过非空、来源归属本会话与流完整性校验；写入 Room 数据库时通过事务比对原记录指纹，防止后台旧摘要覆盖新变更，失败或取消时绝不删除原消息。
- **原始证据回读（`read_task_history`）**：被压缩进检查点的历史记录仍完整保存在本地数据库。模型可调用只读工具 `read_task_history`，按检查点中的来源 ID 有界回读原始消息与工具返回摘录，避免因信息被摘要而重复执行手机操作或命令。
- **DeepSeek 思考模式兼容**：本地重建的检查点与历史投影会明确标为引用数据传入，不会冒充缺失原生推理字段的历史助手消息而触发服务端 400 错误。
