# 会话任务上下文（1.5.5）

## 修复的问题

1.5.4 在后续请求中排除了 Commentary、Tool、Stopped 和 Failed 消息。单轮工具调用期间的完整参数、返回值只存在于内存中的请求，数据库里往往只保存工具显示名称。停止后再次发送消息，模型因而缺少上一轮的执行证据，即使对话仍显示在同一个窗口。

## 当前实现

- 每个助手执行段增加独立的 `executionContext` 字段，持久化工具名称、参数和实际返回结果。执行前写入未确认记录，返回后写入结果；取消时保存中断且未确认的状态。命令读取、状态查询等没有独立界面条目的工具也会记录。
- 停止后立即发送时，先等待上一轮取消清理和停止记录落库，再组装下一条请求，避免读取到尚未更新的状态。
- 请求保留本会话的执行证据、进度报告、停止状态和失败后的部分回复。历史记录作为明确标注的数据发送，不伪造成缺少对应调用的原生 tool 消息，也不构成新的操作授权。
- 明确区分助手报告与工具结果，不将报告自动视为已验证的成功；中断动作可能已经生效，重试前应检查实际状态。历史页面 ID 不允许直接复用。
- 旧版已经保存的进度文字和工具标签可以重新进入上下文。旧版未持久化的工具参数与完整结果不能凭空恢复。
- 文本历史最多保留最近 20 轮用户对话，并按完整轮次限制在约 120,000 个字符以内；每轮活动和单次长输出另外有长度限制，裁剪时标明缺失。图片仍仅在最近 5 轮携带，较旧图片保留文字占位说明。
- 会话上下文独立于长期摘要记忆开关。不开启跨会话记忆，也应能继续本会话任务。
- 数据库 9 → 10 仅增加可空字段，旧聊天和配置无需重置。

## 与 Codex 的关系及边界

核对了本地公开 Codex 源码快照 `b337fe06b7d8d6e5b42295e04c5e92c2b9c46567` 中的：

- `codex-rs/core/src/context_manager/history.rs`：记录消息与工具项，维护模型可见历史，估算上下文占用。
- `codex-rs/core/src/context_manager/normalize.rs`：维护调用与结果的对应关系，对缺失结果补充 aborted 标记。
- `codex-rs/core/src/compact.rs`：构建并持久化压缩后的替代历史及检查点。
- `codex-rs/core/src/codex_thread.rs`：停止、刷新持久化历史与移交运行状态的边界。

本次借鉴的是执行历史独立于显示、持久化中断状态和有界上下文的原则。Floryx 使用自己的 Kotlin 实现，并兼容当前的多家模型接口。

**1.5.5 尚未实现语义压缩。** 1.5.6 已进一步增加独立任务检查点、模型摘要、单轮长任务压缩和原记录回读，替代本节原有的固定轮次裁剪；详见 [会话检查点与压缩](context-checkpoints.md)。该功能独立于用户偏好记忆。

OpenAI 的原生压缩会返回用于后续请求的不透明状态，不能假定它能直接交给 DeepSeek 等其他服务商；多服务商方案需要各自适配或采用可验证的文本摘要。参考 [OpenAI 官方压缩文档](https://developers.openai.com/api/docs/guides/compaction)。
