# 手机操作响应优化与设备验证（2026-10-27）

本轮改善本地观察、等待、视觉比较和滑动反馈。基于当前工作区实施，保留工作区已有的聊天优化。未提升发布版本号，未发布 APK。

## 实现

- 页面读取改为事件唤醒、有限轮询和连续状态确认。稳定的空控件画面也能结束等待，不再为不存在的控件等待六轮。普通观察使用 120 ms 稳定窗口，主动等待预算最多 1.2 s；系统读取自身的阻塞不属于可控等待。
- `wait_for_screen` 使用上次观察作为基线，变化已出现时尽快返回；页面没有变化时保留最多约 700 ms 的等待。只准备一次浮窗，去除原先嵌套的第二次 160 ms 准备，不再无条件先休眠 700 ms。
- 从敏感基线执行允许的 Home/Back 时，等待窗口变化；新出现的敏感页面立即返回并阻止后续操作。避免快速观察过早返回旧敏感窗口、误报导航失败。
- 滑动前缺少可验证的文字列表时，按需保留前后画面，检查像素变化并返回结果图。像素和控件都没有变化才明确报告 `ui_no_change`；仅控件未变化、缺少画面对照时报告 `ui_change_unverified`，引导重新观察。
- 普通文字列表继续优先使用控件状态，避免每次滑动都增加两次截图。已知纯文本模型不接收滑动验证图片，本地验证仍执行。
- 最长边不超过 800 px 的无损 PNG 细节图保留独立内存像素，比较时复用，免去重复 Base64 解码和 PNG 解码；较大图片继续走解码路径。最多随当前局部帧短期持有，不进入聊天持久记录。单张像素数组上限约 2.44 MiB。
- 新增进程内分段计时：模型响应、单个工具、浮窗准备、控件读取、页面等待、手势派发、截图限流、取图、编码和像素比较。环形记录最多 512 条，仅记录阶段、单调时间、耗时和正常返回标记，不保存文字、坐标、图片或凭据。阶段可能嵌套，不能直接求和；“正常返回”也不代表任务成功。

没有更改视觉坐标映射、整图选区后的局部二次定位、点击前像素校验及系统截图保护。截图请求的 500 ms 最小间隔保持不变。

## 本地耗时对照

设备为 MuMu 0、Android 15；通过 MuMuManager 验证 ADB 端点 `127.0.0.1:16384`。优化前先加入测试夹具并构建、安装基线，再修改产品代码；优化后使用同一组测量操作。两轮各预热两次，随后保留五次样本，表格为中位数。测量时没有并行运行构建任务。

| 操作 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 稳定控件页面读取 | 205 ms | 126 ms | 耗时减少 38.5% |
| 读取页面、切换开关并核对新状态 | 618 ms | 388 ms | 耗时减少 37.2% |
| 无可读控件的 Canvas 页面读取 | 1,212 ms | 125 ms | 耗时减少 89.7% |
| 连续 Canvas 截图 | 500 ms | 496 ms | 基本不变，受限流影响 |

额外比较同一组 640×640 合成细节图，在设备上交替执行缓存和解码路径；各预热三次后保留十次样本，逐次断言比较结果相同。缓存像素路径中位数 **2.524 ms**，解码路径 **20.635 ms**。这只说明局部像素比较的开销下降，不能当作整次视觉点击提速比例。

分段记录中，当前合成全图的编码中位数约 132 ms，系统取图约 27 ms，连续截图仍主要受间隔限制。后续图像链路优化应以这些阶段的实测为依据。

这些数据不含模型推理、网络往返或真实 App 的加载耗时；五个样本不能代表长尾延迟，也没有测量真实模型对任意 App 的目标识别成功率。

## 验证和复跑

全量单元测试共 494 项：493 通过，1 项既有 Windows 环境用例跳过，零失败。MuMu 联合回归 JUnit 列出 26 项：25 项通过，付费真实模型用例未启用、跳过 1 项；最终日志为 `OK (26 tests)`，运行约 103 s。

Debug、AndroidTest 和 Release/R8 构建通过。Debug Lint 为 0 错误、178 条警告、3 条提示。一次并发检查遇到 Lint/Kotlin FIR 内部解析异常，使用独立进程、单 worker 重跑后通过；复跑脚本已采用同样参数，没有关闭检查或忽略错误。

优化后的 `Floryx Dev` 已覆盖安装在 MuMu，并完成冷启动。Debug APK 为 `app/build/outputs/apk/debug/app-debug.apk`；Release 产物为 `app/build/outputs/apk/release/app-release-unsigned.apk`，当前没有配置发布签名。没有覆盖实体手机，也没有替换正式下载包。

单元回归覆盖空控件页面、遗漏事件、已发生的变化、显式等待、持续事件、取消、敏感页离开和诊断记录边界；像素比较的缓存与解码路径检查相同输出。设备用例检查真实 Canvas 滑动确实改变颜色，而被忽略的手势仍报告无变化，并回归视觉点击、触点校准、移动目标、旋转、用户接管、敏感/安全窗口、截图传输和浮窗触摸穿透。

回归发现并修复了离开敏感页过早返回的问题。另将两组既有模型链路测试的输入定位限定到 `message_composer_panel`，避免会话抽屉新增搜索框后匹配两个输入框。测试使用合成页面与严格本地模型，没有调用付费模型或操作个人 App。

```powershell
.\scripts\verify-device-performance.ps1 -Label current
```

脚本构建并运行当前代码，不自动还原旧代码生成历史基线。结果保存在忽略目录 `build/device-performance/`。本次原始基线为 `baseline.json`、`baseline-device.log`，优化结果为 `optimized.json`、`pixel-comparison.json`；完整设备结果为 `device-verified.log`。首次回归中的失败日志不计入最终通过统计。
